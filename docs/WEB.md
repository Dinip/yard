# `packages/web`

TanStack Router + TanStack Query + tRPC client + shadcn/ui + Tailwind v4, built
by Vite into static assets served by Caddy.

```
src/
├── main.tsx              router + query client bootstrap
├── styles.css            Tailwind v4 + shadcn OKLCH token set
├── routeTree.gen.ts      generated by @tanstack/router-plugin — never edit
├── lib/
│   ├── trpc.ts           typed client + query client
│   ├── auth-client.ts    better-auth react client (+ admin plugin)
│   ├── types.ts          RouterInputs / RouterOutputs helpers
│   └── utils.ts          cn(), relativeTime()
├── components/
│   ├── app-shell.tsx     header, nav, account menu
│   ├── device-card.tsx
│   └── ui/               shadcn components
└── routes/
    ├── __root.tsx
    ├── login.tsx         public
    ├── _app.tsx          pathless layout — the auth guard
    └── _app/
        ├── devices.index.tsx
        ├── devices.$deviceId.tsx
        ├── providers.tsx
        └── admin.users.tsx
```

## Routing and the auth guard

`_app.tsx` is a **pathless layout route**: it contributes no URL segment but
wraps every authenticated page. Its `beforeLoad` runs before any child loader,
so an authenticated query is never fired while signed out — the redirect to
`/login` happens first, carrying `?redirect=` so the user lands where they meant
to go.

Admin routes add a second `beforeLoad` check against `context.user.role`. That
is a *UX* guard, not a security boundary — `adminProcedure` on the server is the
real one.

## Types flow from the server

`packages/web` depends on `@farm/coordinator` for its **types only**:

```ts
import type { AppRouter } from "@farm/coordinator/router";
```

No coordinator code reaches the bundle. Renaming a tRPC procedure is a
compile-time break in the SPA, which is the point.

Derived types live in `lib/types.ts` (`DeviceListItem`, `AdminUser`, …) rather
than being re-declared, so the UI can never drift from the API shape.

## Single origin

There is no `VITE_API_URL`. In development Vite proxies `/api` to the
coordinator; in production Caddy does. The browser always sees one origin, which
keeps the session cookie `SameSite`-clean and avoids a CORS preflight on every
tRPC batch.

## Styling

Tailwind v4 with the CSS-first config in `styles.css` — no `tailwind.config.js`.
shadcn's "new-york" style, neutral base, OKLCH tokens so the dark theme is a
lightness flip rather than a second hand-tuned palette. Add components with:

```bash
cd packages/web && bunx --bun shadcn@latest add <component>
```

## Not yet built (phase 5)

The device page currently shows details and reserve/release only. Still to come:

- Codec-agnostic `VideoDecoder` canvas renderer, ported from
  `stf-ios-provider/src/frontend/hevc-screen.js` into `src/lib/screen/`. It
  already handles the `{type:"codec"}` handshake, the
  `[0]=key / [1]=delta / [2]=key-with-reset` type byte, and decoder rebuild on
  reset. Generalising it is a matter of taking `codec` + `description` from the
  handshake instead of assuming HEVC. That directory's `INTEGRATION.md`
  documents the framing precisely.
- Input capture, keyboard, clipboard, screenshot, rotate.
- Drag-and-drop install with upload + install progress.
- `/devices/:id/popout` — chrome-free, sized from the device's display geometry
  and DPR via `window.open(url, name, 'width=…,height=…')`. It joins the *same*
  reservation as the parent tab; the provider already fans video out to multiple
  viewers with per-viewer backlog shedding, so no protocol change is needed.
- MJPEG fallback when `VideoDecoder.isConfigSupported` fails or the page is not
  a secure context. Capped at ~3 fps from the existing screenshot primitives,
  honestly degraded, and labelled as such in the UI. No transcode pipeline is
  introduced anywhere.
